> 项目：BMW X3 车主手册智能问答（356 页中文手册）
> 技术栈：LlamaIndex（检索）+ ChromaDB + bge-m3 + bge-reranker-v2-m3
> 记录原则：**每个优化都是一次「假设 → 改动 → 数字验证」**

## 三、实验记录

### 实验 1：页脚噪声清理（数据预处理）

**背景**：PDF 每页末尾有页脚噪声，会污染每个 chunk 的语义。

**发现过程**：
```
① 数据探查      → 发现页脚固定格式：Seite N | 章节 | 页码 | Online Edition
② 抽样踩坑      → 只抽偶数页，误判"格式 100% 稳定"
③ 发现奇偶差异  → 偶数页 5 行（章节分行）、奇数页 4 行（章节合并）
④ 锚点定位      → 用 "Seite " 行定位页脚起点，兼容两种格式
⑤ 章节顺序问题  → 奇数页是「节 章」，偶数页是「章 节」
⑥ 白名单规范化  → 用 6 个章节名判断顺序，统一成 [章, 节]
```

**关键技术点**：
- ❌ 固定偏移 `lines[-5:]` → 遇到奇数页（4 行）错位
- ✅ 锚点定位（从后往前找 `Seite ` 行）→ 两种格式通吃
- ✅ 章节白名单 `{提示, 简要说明, 操作, 驾驶提示, 顺利驾驶, 便捷查阅}`（从数据统计得出，非硬编码）

**结果**：345 个干净 chunk，页脚零残留。

**教训**：
> **抽样要覆盖各种分类**——只抽偶数页导致遗漏了 173 页的另一种格式。

### 实验 2：删除章节模板话（内容级噪声）

**假设**：章节首页有一段模板话（「本章描述了该车型系列中所提供的所有标准装备……」），重复出现在 33 个 chunk 中，稀释语义。

**数据支撑**：
```
含模板话的 chunk: 33 / 345
第34页：模板话 250字 / 全篇 265字  → 94% 是模板话
第39页：模板话 374字 / 全篇 385字  → 97% 是模板话
```

**改动**：用正则删除模板话（**允许中间有换行**，不破坏文档结构）

```python
TEMPLATE_RE = re.compile(r"\s*".join(re.escape(ch) for ch in TEMPLATE))
text = TEMPLATE_RE.sub("", text)
```

**踩坑**：初版用 `text.replace("\n","")` 先把换行全删了再匹配——**破坏了整个文档的段落结构**。改用正则 `\s*` 允许空白穿插，问题解决。

**结果**（检索排名）：

| 问题 | 改之前 | 改之后 | 变化 |
|------|-------|-------|------|
| 胎压数据在哪看？ | #4 | **#2** | ↑2 |
| 多久检查一次轮胎压力？ | #5 | **#3** | ↑2 |
| 雾天自动大灯能识别吗？ | #2 | #2 | — |
| 怎么确认油箱加满了？ | #2 | #2 | — |

**结论**：模板话确实是噪声，删除有效。

### 实验 3：Cross-Encoder 重排（最显著）★

**假设**：向量检索召回没问题（正确答案都在前 5），但**排序不准**（很少排第 1）。

**数据支撑**（检索阶段的分数几乎持平，分不出差别）：
```
问：多久检查一次轮胎压力？
  #1 0.6107 / #2 0.5783 / #3 0.5708 / #4 0.5650 / #5 0.5442   ← 分数挤在一起
```

**改动**：检索 top-20 → cross-encoder 精排 → 取 top-5

**结果**：

| 问题 | 无重排 | **加重排** | 变化 |
|------|-------|-----------|------|
| 胎压数据在哪看？ | #2 | **#1** ✅ | ↑1 |
| 多久检查一次轮胎压力？ | #3 | **#1** ✅ | ↑2 |
| 怎么确认油箱加满了？ | #2 | **#1** ✅ | ↑1 |
| 雾天自动大灯能识别吗？ | #2 | #2 | — |

**Recall@1：0% → 75%**

**关键证据**——重排器拉开了分数差距：
```
重排后：
  #1 0.8611 / #2 0.8189 / #3 0.6064 / #4 0.0768 / #5 0.0751
                                              ↑ 断崖式下降
```

**原理验证**：
| 阶段 | 模型类型 | 分数分布 |
|------|---------|---------|
| 检索 | 双塔（Bi-encoder） | 0.61 / 0.58 / 0.57 / 0.565 / 0.54（几乎持平） |
| 重排 | 交叉编码器（Cross-encoder） | 0.86 / 0.82 / 0.61 / 0.077 / 0.075（拉开差距） |

**双塔只能算余弦相似度，交叉编码器能读懂 query 和 doc 的语义交互**——这是「检索 Phase 分不出细微差别」的根本原因。

### 实验 4：基于字体大小的结构化切分（最有效）★★

**假设**：chunk 粒度偏粗（一页 ≈ 900 字），答案被大量无关内容稀释，重排器难以判断。

**关键发现**：**PDF 里藏着字体信息，字号就是标题层级**。

用 `pypdf` 的 `visitor_text` 回调可以拿到每段文字的字号：

```python
def visitor(text, cm, tm, font_dict, font_size):
    parts.append((round(font_size, 1), text))
page.extract_text(visitor_text=visitor)
```

实测第 155 页的字号层级：

| 字号 | 层级 | 例子 |
|------|------|------|
| 19.0 | 章标题 | 车灯 |
| 14.0 | 节标题 | 自动车灯控制 |
| 11.0 | **子标题（切分点）** | 工作原理、系统的局限性 |
| 10.0 | 小标题（进路径） | 在门柱上 |
| 8.5 | 正文 | ... |
| 5.0 | 页脚 | Seite 155 |

**改动**：
1. 用 `visitor_text` 抽取带字号的片段（替代整页文本抽取）
2. **标题栈**：记录到达当前位置的完整路径（`车灯 > 自动车灯控制 > 系统的局限性`）
3. **字号 ≥ 11.0 处切分**成新小节
4. chunk 文本 = `[标题路径]` + 正文（上下文增强）

**顺带修的 bug**：PDF 的「物理换行」会把句子折断（`自动开启或关` + `闭，例如...`），用「上一片段末尾是否有句末标点」判断是否拼接。

**结果**：

| 问题 | 按页切+重排 | **按小节切+重排** | 变化 |
|------|-----------|-----------------|------|
| 胎压数据在哪看？ | #1 (0.99) | **#1 (0.99)** | — |
| 多久检查一次轮胎压力？ | #1 | #3 ⚠️ | ↓2 |
| **雾天自动大灯能识别吗？** | #2 | **#1 (0.95)** | **↑1 ✅** |
| 怎么确认油箱加满了？ | #1 | **#1 (0.11)** | — |

**最关键的证据**——「雾天」问题：

```
按页切：  #1 第159页(0.5137) / ✅#2 第155页(0.4885)      ← 分数接近，难分伯仲
按小节切：✅#1 第155页(0.9506) /   #2 第159页(0.0769)     ← 断崖式领先
```

**根因**：切分前，答案「传感器无法识别雾天」埋在 900 字整页 chunk 的中间；切分后，它独立成一个 80 字的小节，且带完整路径——

```
[车灯 > 自动车灯控制 > 系统的局限性]
自动车灯控制无法替代驾驶员对环境光线的个人判断。
传感器无法识别诸如雾天和潮湿的天气。在此类情况下，手动开启车灯。
```

**结论**：**切分粒度是 RAG 效果的关键杠杆**。同一套检索 + 重排，只因切分方式不同，同一个问题的分数从「接近」变成「压倒性」。
**技术点**：这叫「上下文增强的 chunk」（contextual chunk）——小块保证检索精确，标题路径补偿上下文。

**踩坑**：
- 初版用 `range(len(lines), -1, -1)` 遍历 → 越界（应从 `len-1` 开始）
- 提高阈值后，低层级标题会变成正文混入（需用「标题栈」保留层级信息）

### 实验 5：索引页过滤 + gold 修正 → 完整评估 ★★★

**背景**：前 4 个实验都是在 4 道测试题上验证的，这次跑**完整的 27 题评估集**。

**第一次评估结果**（27 题）：

```
Recall@1 = 0.70  (19/27)
Recall@3 = 0.89  (24/27)
Recall@5 = 0.93  (25/27)
MRR      = 0.79
```

**排查 2 道未命中的题**，发现两类问题：

**问题 A：索引页噪声**
```
题 25 检索返回: [32, 348, 308, 271, 301]
                        ↑ 第348页是关键词索引（"哑光漆，保养 327 压力，轮胎 284..."）
```
手册第 336-351 页是「从 A 至 Z」关键词索引，**塞满关键词 + 页码**，语义分布特殊，会污染检索结果。
（共 38 个 chunk，占 2%）

**问题 B：gold 标注不全**
```
题 6「油表见底了还能开多远」：
  第149页 [安全提示]: 在可达里程低于 50 公里时可能无法再给发动机供应足够燃油...
  第282页 [加油 > 安全提示]: 在可达里程低于 50 公里时可能无法再给发动机供应足够燃油...
                    ↑ 完全相同的段落出现在两页！gold 只标了 282

题 25「长途出行前应该做哪些检查」：
  gold 标了 [284, 286, 282]，但第 32 页「中途停靠」章节也讲了出行检查
```

**改动**：
1. 过滤索引页（用「中文+数字」配对密度判断，> 8 个即判定为索引页）
2. 修正 gold：题 6 → `[149, 282]`，题 25 → `[32, 284, 286, 282]`
3. 评估脚本加**分类统计**（单点检索题 / 多跳题分开算）

**结果**：

| 指标 | 改之前 | **改之后** | 变化 |
|------|-------|-----------|------|
| Recall@1 | 0.70 | **0.74** | ↑4% |
| Recall@3 | 0.89 | **0.96** | ↑7% |
| **Recall@5** | 0.93 | **1.00** | **↑7%** ✅ |
| MRR | 0.79 | **0.85** | ↑6% |

**分类统计**（更有信息量）：
```
【单点检索题】26 题:  Recall@1=0.77  Recall@3=0.96  Recall@5=1.00  MRR=0.86
【跨章节/多跳题】1 题: Recall@1=0.00  Recall@3=1.00  Recall@5=1.00  MRR=0.50
```

**诚实的说明**：这次提升**不全是技术优化**——
- 索引页过滤是技术优化
- **题 6 / 题 25 的提升主要来自 gold 修正**（补上了遗漏的正确答案）

**但这正是评估工作的价值**：

> 跑评估 → 发现未命中 → 排查根因 → 发现是**标注问题**（而非系统问题）→ 修正标注 → 重跑

**面试可以讲的点**：
> 「我跑评估时发现两题未命中，排查后发现是**手册里同一内容出现在多页**，而 gold 只标了其中一页。
> 补全 gold 后重新评估，Recall@5 从 0.93 提升到 1.00。这让我意识到**评估集的标注质量直接决定评估结论的可信度**。」

**方法论收获**：
1. **分类统计比整体数字更有信息量**——整体 MRR 0.85 掩盖了「多跳题 Recall@1 = 0」这个短板
2. **未命中的题必须逐题排查**——可能是系统问题，也可能是标注问题，不能一律归咎于系统
3. **发现标注错误 ≠ 刷分**——我们补的是「确实包含答案的页」，有原文为证

## 四、待优化项

### ~~问题 1：chunk 粒度偏粗~~ ✅ 已解决（实验 4）

### 问题 1b：展示格式问题（非 bug，已核实）

**现象**：检索输出里出现 `[ > ]` 这样的空路径显示。

**核实结果**：**chunk 数据本身没问题**——路径为空时 `section_text` 不会加前缀。
`[ > ]` 来自 `test_retrieval.py` 的打印格式 `[{chapter} > {section}]`——元数据为空时就显示成 `[ > ]`。

**遗留观察**：`chapter` / `section` 元数据来自「页面标题路径」，与手册的官方章节结构不总是一致。
统计：**94 / 1524 个 chunk 的路径为空**（多为无标题的表格页、数据说明页）。影响不大，但元数据质量可以更好。

**可选方案**：把「页脚章节面包屑」（实验 1 提取的）和「页面标题路径」（实验 4 提取的）**结合起来**——
页脚提供权威的章节归属，标题路径提供更细的层级。

### 问题 2：评估集 gold 标注待校准

**现象 1**：「胎压数据在哪看？」的 gold 标为第 284 页，但检索第 1 名是第 285 页，且 285 页也含答案（「通过门柱上的轮胎压力数据检查」）。

**现象 2**：「多久检查一次轮胎压力？」的 gold 标为第 284 页，但按小节切分后的第 1 名是第 276 页 —— **该页明确写着「每月至少检查轮胎压力两次」**，也是正确答案。

**根因**：手册里**同一知识点在不同章节重复出现**（「节省燃油」章节也讲了胎压检查周期）。

**方案**：评估集改为「**允许多个 gold**」——同一问题的正确答案可能分布在多页/多个小节，只要命中任一即算对。

### 问题 3：手册内部内容重复

**现象**：手册的「简要说明」章节是正文的浓缩版，同一内容出现两次（如加油相关内容在 p32 和 p282）。

**影响**：检索时两处都会被召回，不是 bug，是数据特性。

## 五、方法论总结

整个项目遵循 **「假设 → 改动 → 数字验证」** 的循环：

| 实验 | 假设 | 是否验证 | 影响 |
|------|------|---------|------|
| 1 | 页脚噪声影响切分质量 | ✅ 预处理质量提升 | 基础 |
| 2 | 模板话稀释语义 | ✅ 排名 ↑2 | 中 |
| 3 | 向量检索排序不准 | ✅ Recall@1 0%→75% | **大** |
| 4 | chunk 粒度太粗稀释答案 | ✅ 关键问题 0.49→0.95 | **最大** |
| 5 | 索引页噪声 + gold 标注不全 | ✅ **Recall@5 0.93→1.00** | **大** |

**效果排序：切分粒度 > 重排 > 评估集质量 ≈ 内容清洗 > 页脚清理**
（四者缺一不可——前一个没做好，后一个的效果就被掩盖）

## 七、拒答测试（生成层评估）

**目的**：检索层证明了「能找到答案」，但**还要验证「找不到时会不会编造」**。

**设计**：3 道**手册里没有答案**的问题，系统应该老实说「无法确定」：

| 问题 | 为什么超出范围 |
|------|--------------|
| 这辆车在火星上能开吗？ | 荒谬问题 |
| 换个轮胎要多少钱？ | 手册不含价格信息 |
| 这车和奔驰 GLC 哪个好？ | 手册不含竞品对比 |

**生成 prompt 的三道约束**（来自 rag-from-zero 的设计）：
```
1) 只能依据【参考资料】回答，资料里没有的信息，直接说「根据现有资料无法确定」，绝不编造；
2) 用到资料的地方，用 [编号] 标注来源；
3) 回答简洁，用词通俗。
```

**关键机制**：要求**标 [编号]**——这个动作**逼着模型从资料里找依据**，找不到就自然拒答。

**结果**：**3/3 全部正确拒答**（拒答率 100%）

```
问：换个轮胎要多少钱？
答：根据现有资料无法确定换轮胎的价格。资料里只提到了车轮/轮胎的选用、安装注意事项和
    装配平衡要求[1][2][3]，没有提到任何费用信息。建议咨询授权售后服务经销商...
```

**这个答案值得单独分析**——它有三层结构：
1. **明确拒答**：「无法确定换轮胎的价格」
2. **说明边界**：「只提到了…没有提到费用信息」← 证明它真的读了资料
3. **给出替代建议**：「建议咨询授权售后服务经销商」← 有帮助，不是冷冰冰的拒绝

**对比案例**：在另一个项目（LangChain 客服机器人）里，问「黄赌毒合法吗」，模型**用自己的知识回答了**——
因为 prompt 没强约束。**同样的模型，prompt 设计不同，行为完全不同**。

## 八、项目完整评估结果

```
┌─────────────────────────────────────────────────┐
│  检索层（27 题）                                  │
│    Recall@1 = 0.74   Recall@3 = 0.96            │
│    Recall@5 = 1.00   MRR      = 0.85            │
│                                                  │
│  生成层（3 题拒答测试）                            │
│    拒答率 = 100%  (3/3)                          │
└─────────────────────────────────────────────────┘
```

**一句话总结**：**检索准（前 5 必含答案）+ 不幻觉（没有就拒答）** —— 一个 RAG 系统最核心的两个能力都验证通过了。

**关键原则**：
1. **先看数据再动手**——清理页脚前先做数据探查
2. **一次只改一个变量**——否则分不清效果是谁带来的
3. **抽样要覆盖各种分类**——避免抽样偏差（实验 1 的教训）
4. **别过度清理**——章节名等有信息量的内容要保留
5. **用数字说话**——「感觉变好了」不算数
