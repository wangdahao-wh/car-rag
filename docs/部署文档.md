# Docker 部署文档

> 本文档说明如何把 BMW X3 车主手册 RAG 项目用 Docker 部署为单容器服务。
> 适用环境：已安装 Docker 与 Docker Compose 的 macOS / Linux / Windows（WSL2）。

---

## 一、文件清单

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建应用镜像（Python 3.11-slim + 依赖 + 入口脚本） |
| `.dockerignore` | 构建时排除 `.venv`、`.env`、`data/`、`docs/*.pdf` 等 |
| `docker-compose.yml` | 单服务编排：端口、环境变量、模型卷、索引目录挂载、健康检查 |
| `deploy/entrypoint.sh` | 容器入口：校验索引可用后启动 uvicorn |
| `deploy/rebuild_index.sh` | 用同一镜像跑一次性容器，离线重建 ChromaDB 索引 |
| `docs/部署文档.md` | 本文档 |

---

## 二、架构说明

项目由 FastAPI 通过 `StaticFiles` 托管前端静态页面，因此不需要单独的 Nginx 容器。

```text
宿主机（Mac）
├── data/x3-2024-chunks.json     离线数据工件，不进 Git、不进镜像
├── data/index/                  ChromaDB 索引，挂载进容器
├── hf_models volume             模型权重缓存
└── 容器 car-rag
     ├── uvicorn :8000
     ├── /app/data/index  ← 宿主机 data/index
     └── /models          ← hf_models volume

Windows 客户端
└── http://<Mac-IP>:8000
```

核心原则：

- **镜像只包含代码和依赖，不包含数据。**
- **索引在宿主机离线构建**，运行容器只负责加载索引和提供 API。
- **chunks 只用于建索引**，容器运行时不需要 chunks。
- 数据更新不需要重新构建应用镜像。

## 三、前置准备

### 1. 安装 Docker

确保宿主机已安装 Docker 与 Docker Compose（Docker Desktop 自带 Compose）。

### 2. 配置 API Key

在项目根目录创建 `.env`（已被 `.gitignore` 忽略）：

```bash
cp .env.example .env
```

编辑 `.env`，填入真实 DeepSeek API Key：

```
DEEPSEEK_API_KEY=sk-你的真实key
```

`.env` 通过 `docker-compose.yml` 的 `env_file` 注入容器，不会打进镜像。

### 3. 准备 chunks 数据工件

项目根目录下应有：

```text
data/x3-2024-chunks.json
```

该文件约 800KB，**不提交 Git、不打进镜像**。如果没有，先在本地生成：

```bash
python src/core/build_chunks_new.py
```

目录约定：

```text
data/
├── x3-2024-chunks.json   # 离线输入
└── index/                # ChromaDB 索引，运行容器挂载
```

首次部署前创建索引目录：

```bash
mkdir -p data/index
```

`deploy/rebuild_index.sh` 也会自动创建该目录。

## 四、首次部署

### 1. 构建应用镜像

```bash
docker compose build car-rag
```

### 2. 离线构建索引并启动

```bash
bash deploy/rebuild_index.sh
```

脚本会依次执行：

1. 检查 `.env` 和 `data/x3-2024-chunks.json`；
2. 确保镜像为最新代码（代码未变时走 Docker 缓存）；
3. 停止 `car-rag` 服务；
4. 用同一镜像跑一次性容器执行 `src/core/build_index.py`；
5. 启动 `car-rag` 服务。

首次运行会下载 bge-m3 到 `hf_models` 卷，耗时取决于网络。

### 3. 查看日志

```bash
docker compose logs -f car-rag
```

首次启动流程：

1. `entrypoint.sh` 校验 `data/index` 中的 collection；
2. 校验通过后启动 uvicorn；
3. `lifespan` 加载 bge-m3 + reranker；
4. `/health` 返回 `ready: true`。

首次启动预计 3–8 分钟，之后重启会快很多。

> 容器启动时**不会自动建库**。如果索引不存在，容器会直接报错退出，避免把建库失败误当成服务启动失败。

## 五、验证服务

### 本机验证

```bash
# 健康检查
curl http://127.0.0.1:8000/health
# {"status":"ok","ready":true}

# 正常问答
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"胎压数据在哪看？"}'

# 流式问答
curl -N -X POST http://127.0.0.1:8000/ask/stream \
  -H "Content-Type: application/json" \
  -d '{"question":"雾天自动大灯能识别吗？"}'
```

浏览器打开：<http://127.0.0.1:8000/>

### Windows 客户端验证

1. 在 Mac 上查局域网 IP：

```bash
ipconfig getifaddr en0    # Wi-Fi；有线可能是 en1
```

2. 在 Windows PowerShell 中调用，不要用 `127.0.0.1`：

```powershell
curl.exe -X POST "http://192.168.1.10:8000/ask" `
  -H "Content-Type: application/json" `
  -d "{\"question\":\"胎压数据在哪看？\"}"
```

流式接口：

```powershell
curl.exe -N -X POST "http://192.168.1.10:8000/ask/stream" `
  -H "Content-Type: application/json" `
  -d "{\"question\":\"雾天自动大灯能识别吗？\"}"
```

注意事项：

- macOS 防火墙需要允许 Docker Desktop 接受传入连接；
- Mac 和 Windows 需要在同一局域网；
- Windows 只是客户端，不需要 Docker、模型或数据；
- 如果 Windows 上另起前端页面调用 API，需要在 FastAPI 中配置 CORS；直接打开 `http://<Mac-IP>:8000/` 则同源，不需要 CORS；
- 不要把 8000 端口直接暴露到公网，跨网络测试建议使用 VPN / Tailscale 或加反向代理与鉴权。

## 六、索引与数据更新

### 数据卷 / 目录

| 名称 | 容器内路径 | 内容 | 说明 |
|---|---|---|---|
| `hf_models` | `/models` | bge-m3、bge-reranker 权重 | Docker 命名卷，删除后需重新下载 |
| `./data/index` | `/app/data/index` | ChromaDB 向量库 | 宿主机目录，手动维护 |

`data/index` 必须可写，**不要挂载为 `:ro`**。Chroma 查询时会打开 SQLite，可能产生 WAL/锁文件。

### 重建索引

数据更新后执行：

```bash
bash deploy/rebuild_index.sh
```

脚本内部实际执行的一次性容器命令是：

```bash
docker compose run --rm --no-deps \
  -v "$PWD/data:/app/data" \
  --entrypoint python \
  car-rag src/core/build_index.py
```

使用同一镜像可以保证 ChromaDB、Python 依赖和运行容器完全一致，避免 macOS 宿主机与 Linux 容器的版本差异。

### 备份与回滚

重建前建议备份：

```bash
cp -a data/index data/index.bak
```

如果重建失败或结果不符合预期：

```bash
docker compose stop car-rag
rm -rf data/index
mv data/index.bak data/index
docker compose start car-rag
```

### 只替换 chunks 不会更新索引

容器只挂载 `data/index`，不读取 chunks。只替换 `data/x3-2024-chunks.json` 不会改变检索结果，必须重新执行 `rebuild_index.sh`。

### 清理

```bash
docker compose down -v
```

会删除 `hf_models` 卷；宿主机上的 `data/index` 不会被删除，需要手动清理。

## 七、环境变量

| 变量 | 来源 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | `.env`（`env_file`） | DeepSeek API Key，生成答案必需 |
| `HF_HOME` | `docker-compose.yml` | HuggingFace 模型缓存目录，固定为 `/models` |
| `PYTHONUNBUFFERED` | `docker-compose.yml` | 关闭 Python 输出缓冲，日志实时可见 |

`DEEPSEEK_API_KEY` 只在运行时注入，不会打进镜像。

## 八、健康检查

`docker-compose.yml` 配置：

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
  interval: 30s
  timeout: 10s
  retries: 10
  start_period: 180s
```

- `start_period: 180s`：首次加载模型期间健康检查失败不计入重试次数；
- `/health` 的 `ready` 为 `true` 时健康检查通过。

查看状态：

```bash
docker compose ps
```

## 九、常见问题排查

### 1. 启动报“未找到索引”

```text
[entrypoint] 未找到索引：/app/data/index/chroma.sqlite3
```

说明宿主机 `data/index` 不存在或为空。执行：

```bash
bash deploy/rebuild_index.sh
```

### 2. 启动报“collection 不可用或为空”

索引文件存在，但 ChromaDB collection 缺失或没有数据。重新执行：

```bash
bash deploy/rebuild_index.sh
```

### 3. 建索引报找不到 chunks

```text
FileNotFoundError: data/x3-2024-chunks.json
```

先准备数据工件：

```bash
python src/core/build_chunks_new.py
```

或将已有 chunks 文件放到 `data/x3-2024-chunks.json`。

### 4. 首次启动一直卡在模型下载

bge-m3 约 2GB、bge-reranker 约 1GB，国内网络可能较慢。可在 `docker-compose.yml` 的 `environment` 中加：

```yaml
- HF_ENDPOINT=https://hf-mirror.com
```

### 5. 健康检查一直 unhealthy，`ready: false`

模型尚未加载完成。等待 `start_period` 后仍不正常，查看日志：

```bash
docker compose logs car-rag --tail 200
```

### 6. 端口 8000 被占用

修改端口映射，例如：

```yaml
ports:
  - "8080:8000"
```

### 7. 索引目录写入失败

确认 `docker-compose.yml` 中是：

```yaml
- ./data/index:/app/data/index
```

不要写成 `:ro`。同时确认宿主机 `data/index` 对 Docker 可写。

### 8. Windows 上 entrypoint 报 `\r: command not found`

`Dockerfile` 已通过 `sed -i 's/\r$//'` 统一换行符。若自行修改脚本，保存为 LF 后重新构建。

## 十、生产环境建议

当前配置适合单机演示 / 小规模使用。若要上生产：

1. **索引构建进 CI**：CI 产出索引快照，部署机只拉取索引工件；
2. **索引版本化**：`data/index_v20241023` 之类的目录，评估通过后切换，支持回滚；
3. **外部向量库**：数据量增大后改用 Milvus / pgvector / OpenSearch / Vespa；
4. **GPU 加速**：embedding 与 rerank 改为 GPU 推理；
5. **反向代理**：Nginx / Traefik 处理 HTTPS、限流、鉴权；
6. **资源限制**：`deploy.resources` 限制 CPU / 内存；
7. **监控**：接入 Prometheus + Grafana，监控请求量、延迟、空结果率、索引新鲜度。

## 十一、更新部署流程

### 只更新代码

```bash
docker compose up -d --build
```

索引目录不变，容器重启后继续使用现有索引。

### 更新文档 / 数据

```bash
# 1. 重新生成 chunks（如文档有变化）
python src/core/build_chunks_new.py

# 2. 重建索引并重启应用
bash deploy/rebuild_index.sh
```

**不需要修改应用镜像。** 脚本会做一次增量构建，代码未变时走 Docker 缓存，不会产生新的镜像层。

### 回滚索引

```bash
docker compose stop car-rag
rm -rf data/index
mv data/index.bak data/index
docker compose start car-rag
```
