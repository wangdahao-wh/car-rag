# Docker 部署文档

> 本文档说明如何把 BMW X3 车主手册 RAG 项目用 Docker 部署为一个单容器服务。
> 适用环境：已安装 Docker 与 Docker Compose 的 Linux / macOS / Windows（WSL2）。

---

## 一、新增 / 修改的文件清单

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 构建应用镜像（Python 3.11-slim + 依赖 + 入口脚本） |
| `.dockerignore` | 构建时排除 `.venv`、`.env`、`data/index`、`docs/*.pdf` 等 |
| `docker-compose.yml` | 单服务编排：端口映射、环境变量、数据卷、健康检查 |
| `deploy/entrypoint.sh` | 容器入口：索引不存在时自动构建，再启动 uvicorn |
| `docs/部署文档.md` | 本文档 |

---

## 二、架构说明

项目本身已经由 FastAPI 通过 `StaticFiles` 托管前端静态页面，因此 **不需要单独的 Nginx 容器**，一个容器即可同时提供 API 和前端。

```text
┌────────────────── 容器 car-rag ──────────────────┐
│  uvicorn (src.api.main:app, :8000)               │
│    ├─ /ask, /ask/stream, /health  (API)          │
│    └─ /  (静态前端 static/)                      │
│  依赖：                                           │
│    ├─ bge-m3 + bge-reranker  (HF_HOME=/models)   │
│    └─ ChromaDB 索引  (/app/data/index)           │
└──────────────────────────────────────────────────┘
          ▲                       ▲
          │                       │
     hf_models volume        rag_index volume
   (模型权重，约 3GB)       (向量库，约 15MB)
```

两个持久化卷的意义：

- **hf_models**：缓存 HuggingFace 模型权重。bge-m3（~2GB）+ bge-reranker-v2-m3（~1GB）首次启动时下载，之后重启不再下载。
- **rag_index**：ChromaDB 向量库。首次启动由 `entrypoint.sh` 从 `data/x3-2024-chunks.json` 自动构建，之后持久化。

## 三、前置准备

### 1. 安装 Docker

确保宿主机已安装 Docker 与 Docker Compose（Docker Desktop 自带 Compose）。

### 2. 配置 API Key

在项目根目录创建 `.env`（已被 `.gitignore` 忽略）：

```bash
cp .env.example .env
```

编辑 `.env`，填入你的 DeepSeek API Key：

```
DEEPSEEK_API_KEY=sk-你的真实key
```

> `.env` 通过 `docker-compose.yml` 的 `env_file` 注入容器，应用内 `os.getenv("DEEPSEEK_API_KEY")` 直接读取。

### 3. 确认 chunks 数据存在

项目根目录下应有 `data/x3-2024-chunks.json`（约 800KB）。该文件会被打进镜像，作为构建向量库的数据源。

如果没有，先在本地生成一次：

```bash
python src/core/build_chunks_new.py
```

## 四、构建与启动

### 方式一：Docker Compose（推荐）

```bash
# 构建镜像并后台启动
docker compose up -d --build

# 查看日志（首次启动会下载模型，耗时较久）
docker compose logs -f car-rag
```

首次启动流程：

1. 拉取 Python 3.11-slim 基础镜像
2. 安装 `requirements.txt` 中的依赖（含 torch，较慢）
3. 容器启动，`entrypoint.sh` 检测到索引不存在 → 执行 `build_index.py`（此时会下载 bge-m3 模型到 `/models`）
4. 索引构建完成 → 启动 uvicorn
5. `lifespan` 加载 bge-m3 + reranker 模型 → 服务就绪

首次启动预计耗时 3–8 分钟（取决于网络与 CPU），之后重启秒级启动。

### 方式二：纯 Docker

```bash
# 构建镜像
docker build -t car-rag:latest .

# 创建数据卷
docker volume create hf_models
docker volume create rag_index

# 运行容器
docker run -d \
  --name car-rag \
  -p 8000:8000 \
  --env-file .env \
  -e HF_HOME=/models \
  -v hf_models:/models \
  -v rag_index:/app/data/index \
  car-rag:latest
```

## 六、数据卷与持久化

| 卷名 | 容器内路径 | 内容 | 重建成本 |
|---|---|---|---|
| `hf_models` | `/models` | bge-m3、bge-reranker 权重 | 高（重新下载约 3GB） |
| `rag_index` | `/app/data/index` | ChromaDB 向量库 | 低（约 1 分钟从 chunks 重建） |

### 重建向量库

如果更新了 chunks，需要重建索引：

```bash
# 方式 1：删除卷后重启，entrypoint 会自动重建
docker compose down
docker volume rm car-rag_rag_index
docker compose up -d

# 方式 2：在运行中的容器内手动构建
docker compose exec car-rag python src/core/build_index.py
docker compose restart car-rag
```

### 清理所有数据（慎用）

```bash
docker compose down -v
```

这会同时删除 `hf_models` 和 `rag_index`，下次启动需要重新下载模型并重建索引。

## 七、环境变量说明

| 变量 | 来源 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | `.env`（`env_file`） | DeepSeek API Key，生成答案必需 |
| `HF_HOME` | `docker-compose.yml` | HuggingFace 模型缓存目录，固定为 `/models` |
| `PYTHONUNBUFFERED` | `docker-compose.yml` | 关闭 Python 输出缓冲，日志实时可见 |

> `DEEPSEEK_API_KEY` 只在运行时通过环境变量注入，不会被打进镜像（`.env` 在 `.dockerignore` 中）。

## 八、健康检查

`docker-compose.yml` 配置了健康检查：

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
  interval: 30s
  timeout: 10s
  retries: 10
  start_period: 180s
```

- `start_period: 180s`：首次启动有 3 分钟宽限期，期间健康检查失败不计入重试次数。
- 服务启动后 `ready` 字段为 `true` 时健康检查通过。

查看健康状态：

```bash
docker compose ps
```

## 九、常见问题排查

### 1. 首次启动一直卡在模型下载

正常现象。bge-m3 约 2GB、bge-reranker 约 1GB，国内网络可能较慢。可设置 HuggingFace 镜像加速（修改 `docker-compose.yml` 的 `environment`）：

```yaml
environment:
  - HF_HOME=/models
  - HF_ENDPOINT=https://hf-mirror.com
  - PYTHONUNBUFFERED=1
```

### 2. 健康检查一直 unhealthy，`ready: false`

`RAGService` 尚未初始化完成（`lifespan` 中加载模型需要时间）。等 `start_period` 过后再看。如果超过 3 分钟仍未就绪，查看日志：

```bash
docker compose logs car-rag --tail 200
```

### 3. 启动报错 `Collection bmw_x3_manual does not exist`

说明向量库卷为空且 `entrypoint.sh` 构建索引失败。常见原因：

- `data/x3-2024-chunks.json` 没有被打进镜像（检查 `.dockerignore` 是否误排除了 `data/*.json`）；
- 模型下载失败导致 `build_index.py` 报错。

### 4. 端口 8000 被占用

修改 `docker-compose.yml` 的端口映射，例如改为 `8080:8000`。

### 5. 在 Windows 上 `entrypoint.sh` 报 `\r: command not found`

`Dockerfile` 中已通过 `sed -i 's/\r$//'` 统一换行符。若自行修改了脚本后重新构建，确保保存为 LF 格式即可。

## 十、生产环境建议

当前配置适合单机演示 / 小规模使用。若要上生产，建议：

1. **GPU 加速**：embedding 与 rerank 改为 GPU 推理，显著降低首字延迟；
2. **模型预热**：把模型权重打进镜像（构建时 `huggingface-cli download`），消除首次启动下载；
3. **反向代理**：前面加 Nginx / Traefik，处理 HTTPS、限流、跨域；
4. **资源限制**：在 `docker-compose.yml` 加 `deploy.resources` 限制 CPU/内存；
5. **日志收集**：把日志接到 ELK / Loki；
6. **监控**：对接 Prometheus + Grafana，监控请求量、延迟、模型加载状态。

# 重新构建并启动
