# 汽车知识库智能问答（BMW X3 车主手册 RAG）

> 基于 **356 页真实车主手册** 的 RAG 问答系统。
> 检索 **Recall@5 = 1.00**，拒答率 **100%**，含 **5 组对比实验**。

车主问「胎压数据在哪看？」，系统检索到手册第 284 页，给出带页码引用的答案——**而不是让大模型凭记忆瞎答**。

## 核心亮点

### 1. 用 PDF 字体层级做结构化切分 ★

**问题**：一页 ≈ 700 字，混了多个小节，答案被稀释。检索「雾天自动大灯能识别吗」，正确答案在第 155 页中段，但整页 chunk 语义太杂，重排后排不到第一。

**解法**：发现 **PDF 里藏着头层级信息**——用 `pypdf` 的 `visitor_text` 回调拿到每段文字的字号：

| 字号 | 层级 |
|------|------|
| 19.0 | 章标题 |
| 14.0 | 节标题 |
| **11.0** | **子标题（切分点）** |
| 10.0 | 小标题（进路径） |
| 8.5 | 正文 |
| 5.0 | 页脚 |

**效果**：同一个问题，重排分数从 **0.49 → 0.95**（第二名只有 0.077），切分粒度细化 **6.7 倍**（686 字 → 99 字中位）。

### 2. 带标题路径的 chunk（上下文增强）

每个 chunk 的文本以**完整标题路径**开头：

```
[车灯 > 自动车灯控制 > 系统的局限性]
自动车灯控制无法替代驾驶员对环境光线的个人判断。
传感器无法识别诸如雾天和潮湿的天气。在此类情况下，手动开启车灯。
```

小块保证检索精确，标题路径补偿上下文——既是好的检索线索，也是好的引用格式。

### 3. 数据清洗踩过的坑（真实细节）

| 问题 | 发现方式 |
|------|---------|
| 页脚噪声（`Seite 155` / `Online Edition`） | 数据探查 |
| **偶数页 5 行页脚、奇数页 4 行** | 抽样时只抽了偶数页，误判「格式统一」，后来才发现 |
| 章节模板话（占全篇 94%-97%） | 统计重复段落 |
| 目录页 / 索引页噪声 | 分析未命中的检索结果 |

### 4. 评估驱动，不靠感觉

5 组对比实验，每组都是「**假设 → 改动 → 数字验证**」：

| # | 假设 | 结果 |
|---|------|------|
| 1 | 页脚噪声影响切分质量 | ✅ 预处理质量提升 |
| 2 | 模板话稀释语义 | ✅ 排名 ↑2 |
| 3 | 向量检索排序不准 | ✅ Recall@1 **0% → 75%** |
| 4 | chunk 粒度太粗 | ✅ **0.49 → 0.95** |
| 5 | 索引页噪声 + gold 标注不全 | ✅ **Recall@5 0.93 → 1.00** |

详见 [`docs/实验记录.md`](docs/实验记录.md)。

### 5. 发现并修正评估集自身的错误

跑评估时发现 2 题未命中，排查后**不是系统问题，而是标注问题**——

> 手册里同一段话出现在两页（第 149 页和第 282 页），而 gold 只标了其中一页。

补全 gold 后 Recall@5 从 0.93 提升到 1.00。**这说明评估集的标注质量直接决定评估结论的可信度。**

## 技术架构

```
┌──────────────────────────────────────────────────────────┐
│  FastAPI 接口层                                           │
│    POST /ask          同步问答（答案 + 引用来源）            │
│    POST /ask/stream   流式问答（SSE，逐字输出）             │
│    GET  /health       健康检查                            │
│    GET  /docs         自动生成的交互式 API 文档             │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│  检索层（LlamaIndex）                                      │
│    ① 向量检索（bge-m3，top-20）                            │
│    ② Cross-Encoder 重排（bge-reranker-v2-m3，top-5）       │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│  生成层（DeepSeek）                                        │
│    带引用的答案生成 + 超纲拒答                              │
└──────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────┐
│  数据层                                                   │
│    ChromaDB 向量库 + 1483 个带标题路径的 chunk              │
└──────────────────────────────────────────────────────────┘
```

**离线建库链路**：

```
PDF (356 页)
  ↓ extract_blocks()   用字体信息抽取片段 + 剔除页脚
  ↓ build_sections()   按字号 ≥ 11 切分，标题栈维护路径
  ↓ section_text()     拼成 "[标题路径] + 正文"（含折行修复）
x3-2024-chunks.json    （1483 个 chunk，中位 99 字）
  ↓ build_index()      bge-m3 向量化 + 存 ChromaDB
data/index/
```

## 快速开始

### 1. 安装依赖

```bash
cd car-rag
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

> 首次会下载 bge-m3（约 2GB）和 bge-reranker-v2-m3

### 2. 配置 API Key

```bash
cp .env.example .env
# 编辑 .env，填入 DEEPSEEK_API_KEY
# 申请地址：https://platform.deepseek.com/api_keys
```

### 3. 建库（只需一次）

```bash
python src/core/build_chunks_new.py    # 切分（约 10 秒）
python src/core/build_index.py         # 向量化 + 入库（约 1 分钟）
```

### 4. 启动服务

```bash
python -m uvicorn src.api.main:app --reload --port 8000
```

打开 **http://127.0.0.1:8000/docs** 可以直接在浏览器里测试接口。

### 5. 或直接调接口

```bash
# 同步
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"胎压数据在哪看？"}'

# 流式（-N 关闭缓冲，否则看不到流式效果）
curl -N -X POST http://127.0.0.1:8000/ask/stream \
  -H "Content-Type: application/json" \
  -d '{"question":"雾天自动大灯能识别吗？"}'
```

### 6. 跑评估

```bash
python eval/evaluate.py       # 检索评估（Recall@k / MRR）
python eval/test_refuse.py    # 拒答测试
```

## 已知局限

| 局限 | 说明 | 可能的方向 |
|------|------|-----------|
| **术语不匹配** | 用户说「抬头显示」，手册叫「全彩平视显示系统」，检索精度下降 | Query 改写 / 同义词扩展 |
| **多跳问题** | 跨章节问题（答案分散在多页）Recall@1 = 0 | 子问题分解、多轮检索 |
| **元数据粒度** | `chapter`/`section` 字段存的是页内标题路径，非官方章节 | 结合页脚面包屑 |
| **无多轮对话** | 每次问答独立，不记得上下文 | 会话管理 + 历史拼接 |
